# SDDP Apartment

Public marketing website and a progressive CRM for SDDP Apartment in San Kamphaeng, Chiang Mai.

Guests can check live room availability, send an inquiry, and contact the team on phone or Line. Staff can follow those inquiries, convert a booked guest into a resident record, and check people out so the public room board updates.

## What is live now

- Customer website in English, Thai, and Burmese
- Live availability from resident records (no private guest data on the public page)
- Inquiry form into a staff pipeline: new → contacted → booked → moved in
- Encrypted passport storage after staff confirm consent
- Render Starter hosting with a persistent SQLite disk for CRM and invoices

This stays on Render Starter. Keep the onrender.com URL, and keep guest contact on phone and Line. No custom domain or mail server is required.

## Local preview

```bash
npm install
cp .env.example .env
# set ADMIN_PASSWORD and a 32-byte base64 GUEST_DATA_ENCRYPTION_KEY
npm run dev
```

Create an encryption key with:

```bash
openssl rand -base64 32
```

Open `/admin` on localhost to use the local preview login, or set `ADMIN_PASSWORD` and sign in with that password.

## Render (production host)

Stay on **Starter** with a persistent disk. Do not use Free: that disk is wiped on sleep and redeploy.

1. Push this repository to GitHub.
2. In Render, create a **Web Service** from the repo, or use `render.yaml`.
3. Instance type: **Starter**. Attach a **1 GB disk** at `/var/data`.
4. Runtime: Node 22. Build: `npm ci && npm run build`. Start: `npm start`.
5. Set `ADMIN_PASSWORD` and `GUEST_DATA_ENCRYPTION_KEY` in the Render dashboard. `ADMIN_SESSION_SECRET` can be generated by Render.
6. Set `SDDP_DB_PATH` to `/var/data/sddp.sqlite`.

Keep the public site on `*.onrender.com`. No custom domain or mail server. Guests already reach you on phone and Line.

Starter stays online (no 15-minute sleep). Typical cost is about $7/month plus $0.25/month for 1 GB disk.

This project does not use other websites or their git remotes.

## Optional alerts

SDDP can reuse the existing Hostinger n8n instance. Install a **new** workflow named **SDDP Inquiry Alert**. Do not edit BCC or PDF workflows.

1. In n8n, import `n8n/sddp-inquiry-alert.json` (replace the previous SDDP Inquiry Alert if it already exists).
2. Set n8n env `SDDP_N8N_WEBHOOK_SECRET` and `SDDP_ALERT_EMAIL`. Attach an **SDDP Gmail** credential (not the BCC or PDF workflow).
3. Optional bank fallbacks if the admin bank fields are empty: `SDDP_BANK_NAME`, `SDDP_BANK_ACCOUNT_NAME`, `SDDP_BANK_ACCOUNT_NUMBER`, `SDDP_BANK_PROMPTPAY`.
4. Activate **SDDP Inquiry Alert**. The webhook path is `/webhook/sddp-inquiry-alert`.
5. On Render, set `N8N_INQUIRY_WEBHOOK` to that URL and `N8N_WEBHOOK_SECRET` to the same secret.

Each website inquiry then:
- saves in the CRM first
- emails the **guest** a professional deposit letter (50% to reserve, non-refundable if they do not arrive, bank details, send slip to Line)
- emails **staff** the same lead, so you can mark **Deposit ✓** after the slip arrives

Passport numbers are never included in those alerts.
